## 3. Phase 7: Learnings That Feed Back into `omnicoach` (Stages A, B & C)

1. **L1 — Monotonicity of `Roots(h)` across shared intermediate types (`u -> v ⇒ Roots(u) ⊆ Roots(v)`) is required for rule satisfiability (F11)**:
   - *Observation*: In `ripgrep_glob`, `Glob` contains a `Tokens` field (`Containment`), while `GlobBuilder::build` calls `Tokens::to_regex_with`, whose `impl Tokens` body calls the private helper `char_to_escaped_literal`. Because module-scope behavior of `impl Tokens` rolls up onto the `Tokens` type node (F6), `Roots(char_to_escaped_literal)` traverses `Glob -> Tokens -> char_to_escaped_literal` and assigns `owners = [Glob, GlobBuilder]`.
   - *Why current behavior is correct*: Because `Tokens` is referenced by both `Glob` and `GlobBuilder`, `Tokens` must be placed in Place 2 (the trailing shared section after both `Glob` and `GlobBuilder`). Since `Tokens` calls `char_to_escaped_literal`, `callee-before-caller` requires `pos(Tokens) < pos(char_to_escaped_literal)`, which forces `char_to_escaped_literal` into Place 2 below `Tokens` as well. If `Roots(char_to_escaped_literal)` were `{GlobBuilder}` (`|Roots| = 1`) instead of `{Glob, GlobBuilder}`, (a) `uncolocated-helper` and `callee-before-caller` would contradict each other whenever `GlobBuilder` precedes `Glob` and has Place 1 helpers, and (b) `Shared(Glob, GlobBuilder)` (`Tokens`) would depend upward on `Owner(GlobBuilder)` (`char_to_escaped_literal`). Thus `u -> v ⇒ Roots(u) ⊆ Roots(v)` is an essential invariant of ADR 011.
2. **L2 — Multi-scale levelization mirrors ADR 006 + ADR 011's actual reading order (F9, F12)**:
   - *Observation*: Computing Lakos levels globally across a flat graph conflates distinct containment scales. Levelizing independently at each scale (`Component` DAG $\to$ intra-component `Module` DAG $\to$ intra-module `Owner` DAG $\to$ intra-owner `Declaration` DAG) achieves `M2 = 0 / 0` across every module and project benchmark.
   - *Implication*: Any future diagnostic, auto-fixer, or documentation export that reports abstraction levels should compute levels locally within each parent container.
3. **L3 — Shared-bucket fragmentation signals when a module is a flat utility hub (F10)**:
   - *Observation*: When `#{Shared(S) buckets}` approaches or exceeds `#{Owner(p) groups}` (as in `ast/rust.rs`: `18` shared buckets across `29` public functions), the module does not decompose into independent vertical components—it is a horizontal utility hub serving many entrypoints.
   - *Implication*: The ratio `shared_groups / owner_groups` is a direct cohesion metric for whether a file benefits from intra-module component folding vs. module-level decomposition.
4. **L4 — Blind `Outline` vs. `Source-only` subagent evaluation across 24 questions and 4 conditions (`M4`)**:
   - *Observation*: Under an unlimited budget on `QB1`–`QB5`, `Outline-only` and `Source-only` both scored `5 / 5 (100%)`, but `Outline-only` required **5 tool calls (~65s)** vs. **37 tool calls (~300s)** (`7.4×` fewer tool calls).
   - *24-Question Equal-Budget Matrix (`6 categories × 4 projects`, `≤12` read calls)*:
     - `Outline: ModuleOnly` (`0.8%–4%` bytes, `5` calls): **`12.0 / 12 (100%)`** on macro architecture, reflexion, cycles, and cross-module blast radius (`Q1`–`Q3`); `12.0 / 24 (50.0%)` overall.
     - `Outline: PublicSurface` (`3%–12%` bytes, `7` calls): **`15.5 / 16 (96.9%)`** on macro + public API surface questions (`Q1`–`Q4`); `16.5 / 24 (68.8%)` overall.
     - `Outline: Full` (`22%–57%` bytes, `10` calls): **`24.0 / 24 (100.0%)`** across all 6 question categories (`Q1`–`Q6`).
     - `Source-Only (≤12-call budget)` (`11` calls): **`18.5 / 24 (77.1%)`** overall — collapsing to **`31.3% (1.25 / 4)`** on cross-module blast radius (`Q3`) due to file-count/size limits and losing points on non-local invariants (`Q5.omnicoach` private-only ownership reachability and `Q6.cpython_zoneinfo` class-method placement findings).
5. **L5 — 3-Way Reflexion Model (`D30`) catches unused architecture declarations (`Absent` edges, F14)**:
   - *Observation*: Comparing `define_architecture!` in `src/architecture.rs` against actual cross-module references in `src/` surfaced that `CodeLintSuppression => [CodeLintContract, ...]` declares a dependency on `CodeLintContract` with `0` actual references in `src/code_lint/suppression.rs`.
   - *Decision*: Kept as an informational insight in the graph export only; `define_architecture!` expresses *allowed* conceptual dependencies rather than mandatory edges.
6. **L6 — Module-level SCCs expose intra-component module cycles invisible to component conformance (F15)**:
   - *Observation*: Even when component dependencies form a strict DAG, intra-component modules can form cycles (such as `rule_declaration <-> rule_declaration::options` in `omnicoach`, or the 7-module SCC in `ripgrep/crates/ignore`).
   - *Implication*: Added to `ROADMAP.md` (`## Architecture & Conformance`) as a future enhancement.
7. **L7 — `PublicSurface` mode should project `Owner(p) -> Owner(q)` summary edges onto public declarations (`F18`)**:
   - *Observation*: In `Q4.cpython_zoneinfo`, `reset_tzpath` encapsulates `InvalidTZPathWarning` transitively through private helper `_parse_python_tzpath`. Dropping private items in `PublicSurface` without projecting `Owner(p) -> Owner(q)` summary edges hid that indirect public-to-public dependency (`3.5 / 4` on `Q4`).
   - *Resolution*: Implemented in `src/code_lint/graph/builder.rs` (`extract_public_surface_module`), closing `F18`.
8. **L8 — Bidirectional edges (`->` and `<-`) + `:start..end` spans reduce token count (`-14.8%` bytes, `-38.8%` lines) while raising 1-step refactoring accuracy from `56.3%` to `100.0%` ([08_stage_c_agent_formats.md](08_stage_c_agent_formats.md))**:
   - *Observation*: `F1_Outline` omits `end_line` and incoming `<-` edges. When planning 1-step ADR 011 edits (`T2`), the `F1_Outline` agent was off by `1–17` lines on 7 of 8 tasks (`4.5 / 8 = 56.3%`) because doc comments, `impl` blocks, and EOF cannot be inferred from the next item's start line. Adding `:start..end` and `<- used_by` in `F2_CompactBi` raised `T2` accuracy to **`8.0 / 8 (100%)`** and halved agent search steps (`6` steps / `11` tool calls vs. `13` steps / `21` tool calls) while shrinking total byte count by `14.8%`.
9. **L9 — Inline language signatures & field summaries (`F3_AnnotatedStubs`) are essential for Zero-Read API Synthesis on non-stdlib code (`100%` vs. `25%` on `omnicoach`)**:
   - *Observation*: On project-specific APIs (`omnicoach` `T3.1` and `T3.2`) where LLM pretraining cannot supply signatures, symbol-only graph formats (`F1_Outline` and `F2_CompactBi`) scored only **`25% (0.5 / 2.0)`**, hallucinating parameter counts, parameter order, and struct fields. Embedding 1-line Rust/Python signatures and struct/enum/class fields in `F3_AnnotatedStubs` raised `T3` accuracy to **`8.0 / 8 (100%)`** (`24.0 / 24 = 100%` overall) at `27.2%` of source bytes (`21%` fewer lines than `F1_Outline`).
10. **L10 — Machine-oriented YAML (`F4_StructuredYaml`) adds `+45.6%` byte overhead (`+91.8%` lines) over `F3_AnnotatedStubs` with zero accuracy gain**:
    - *Observation*: Both `F3_AnnotatedStubs` and `F4_StructuredYaml` scored **`24.0 / 24 (100%)`**, but `F4_StructuredYaml` required `903 KB` (`13,028` lines) vs. `620 KB` (`6,792` lines) for `F3_AnnotatedStubs` across the 4 projects due to repeated key names and quoting.
11. **L11 — Method-level attribution (`Type::method`) on both source and target endpoints is a mandatory prerequisite for query slices ([12_stage_d_results.md](12_stage_d_results.md) §2)**:
    - *Observation*: Prior to Stage D, `collect_intra_file_references` and `enclosing_scope_symbol` attributed references inside `impl Type { fn method() }` to the outer `Type`, and `longest_module_prefix` / `resolve_rust_target` matched only full module paths (`m::Type`), dropping two-segment associated calls (`Type::method()`) to `0.0%` (`0/136`) cross-module recall. Fixing both endpoints raised Rust SCIP exact symbol-to-symbol recall from **`71.5%` to `86.6%` (`+15.1 pp`)**, cross-module `Type::method` recall from **`0.0%` to `100.0%` (`136/136`)**, and literal precision from **`84.6%` to `98.4%`** in `0.46 s` full-repo build time.
12. **L12 — Task-shape crossover between single-file hierarchy (`omnicoach graph <file>`) and cross-module queries (`find`/`slice`/`place`/`impact`) ([12_stage_d_results.md](12_stage_d_results.md) §4.2)**:
    - *Observation*: Across `84` controlled live subagent runs, single-file `omnicoach graph <file>` beat 1-hop `slice` on intra-file multi-hop bugfixes where the target file was named in the prompt (Tarjan SCC bugfix in `ast.rs`: `-76.0%` vs. `-48.6%` tokens; `ripgrep` bugfix in `dir.rs`: `-67.0%` vs. `-60.5%` tokens) because `omnicoach graph <file>` renders the full 4-hop intra-file hierarchy in 1 turn (`4–12 KB`). Conversely, `find`/`slice`/`place`/`impact` beat File/Directory Graph on cross-module bugfixes (`-8.1%`), multi-file ADR 012 refactors (`-16.3%` to `-25.1%`), ADR 011 placement (`-15.9%` tokens, `-22.5%` wall time, `-40.6%` fewer post-lint retries), and repository-wide comprehension (`-30.2%` on `inherit`, `-65.4%` to `-74.8%` on `flash`).
    - *Tool surface since*: `place` and `impact` were removed before landing (`D63`); pre-edit placement is now served by the conflict-free anchor in `omnicoach code` diagnostics, and `find` and `slice` remain.
13. **L13 — Closed-loop compiler/linter oracles mask binary pass/fail differences on code edits; open-ended comprehension exposes accuracy gains ([12_stage_d_results.md](12_stage_d_results.md) §5.1)**:
    - *Observation*: When `cargo test` and `omnicoach code` are available, Baseline agents eventually reach `100%` pass rate via `15`–`30` brute-force search/read calls and `10`–`15` edit-lint-move retries, making **trajectory efficiency** (`-38.4%` to `-45.0%` cost-weighted tokens, `-52.5%` fewer pre-edit search/read calls) the primary gain on code tasks. On open-ended **Architectural Comprehension** (no test oracle), Query Subcommands raised rubric accuracy from `91.7%` (`inherit`) / `83.3%` (`flash`) to **`100.0%`**, and enabled **`flash` + Turn-1 Query CLI (`473K` tokens, `374 s`) to beat `inherit` + Baseline (`579K` tokens, `429 s`) by `-18.2%` in tokens and `-12.8%` in wall time**.
14. **L14 — The `10 KB` agent-harness inline stdout truncation boundary is the hard budget ceiling for CLI graph tools ([12_stage_d_results.md](12_stage_d_results.md) §5.3 & §6.3)**:
    - *Observation*: When an agent runs a command whose stdout exceeds `~10 KB` (`10,240` bytes)—such as bare `omnicoach graph .` (`307–700 KB`) or unguarded multi-symbol slices—the agent harness truncates the middle of the output inline and spills to a step log file, causing `flash` in the initial File/Directory Graph comprehension condition to consume **`+14.7%` more tokens than Baseline (`1.88M` vs. `1.64M`)**. Guarding multi-file full graphs at `8 KB` (`MAX_MULTI_FILE_FULL_GRAPH_BYTES = 8_192`) with `2`-peer module edge capping (`7,085` bytes inline) eliminated the regression and reduced `flash` comprehension tokens by **`-72.2%` (`1.88M → 523K`)** and wall time by **`-50.5%` (`816 s → 404 s`)** (`L14`).
    - *Tool surface since*: The size-triggered `8 KB` guard was replaced by a target-dependent default depth (`D65`): a directory renders at module depth by default (`omnicoach graph src` is `8.9 KB` on this repository), so the module overview the guard fell back to is now the default, while an explicit `--depth` is always honored.
15. **L15 — Single-rule anchor selection (`best_anchor`) causes 2-move ADR 011 lint cascades unless scored against all of the moved item's own constraints ([12_stage_d_results.md](12_stage_d_results.md) §6.1)**:
    - *Observation*: Scoring candidate insertion slots by `(broken_held, distance, pos)` for a single violated rule (`private-before-public`) can recommend a slot above a private caller/type where `callee-before-caller` is violated on the moved item itself, forcing a second move. Scoring by the 4-tuple `(broken_held, unfixed_own, distance, pos)` guarantees single-move convergence whenever a conflict-free slot exists.
16. **L16 — Identifier-token overlap fallback (`MatchRank::TokenOverlap`) prevents 20-turn search spirals when prompt/agent symbol names drift from source identifiers ([12_stage_d_results.md](12_stage_d_results.md) §6.2 & §6.5)**:
    - *Observation*: When a prompt or agent refers to a concept by a composite camelCase/snake_case name (`RuleSelectionConfig`) whose source struct is named slightly differently (`rule_selection::RawSelection`), contiguous substring matching returns `(0 matches)` and triggers `20+` exploratory search turns. Splitting unmatched queries into camelCase/snake_case identifier tokens (`len > 2`) and ranking declarations matching `>= 2` qualified tokens and `>= 1` symbol token resolves the target module's declarations on the first call.
    - *Tool surface since*: `MatchRank::TokenOverlap` was removed before landing (`D64`); the evidence came from a single task and the token split returns noisy hits.

| **D60** | **Propagate `roots: Vec<String>` (`Roots(item)`) on `CallOrderFinding` and render ownership-aware `[uncolocated-helper]` diagnostics (`Shared` vs. `Exclusive`).** | Previously, `uncolocated-helper` formatted both `Ownership::Owner(caller)` and `Ownership::Shared` findings with the same template claiming the helper was separated from `caller`'s inline cluster. ## 7. Landing Decisions (`D63`–`D66`)

| ID | Decision | Rationale |
| :--- | :--- | :--- |
| **D63** | **Remove `omnicoach graph place` and `omnicoach graph impact`**, together with the placement simulator in `src/code_lint/ast/call_clusters.rs` (`simulate_item_placement`, `HypotheticalItem`, `SimulatedPlacement`, `InsertionSlot`, `evaluate_candidate_slots`) and `impact`'s `render_divergent_edges` in `src/code_lint/graph/query.rs`. ADR 011 placement has one engine: `best_anchor`, surfaced through `omnicoach code` diagnostics. The remaining graph queries are `find` and `slice`. | `place` was a second ADR 011 placement engine duplicating `best_anchor`. The two diverged: the index-shift and slot-scoring defects recorded in [13_stage_e_diagnostic_placement_design.md](13_stage_e_diagnostic_placement_design.md) §5 are that divergence, and `D61`/`D62` patched the copy instead of removing it. Every agent runs `omnicoach code` after editing, so ownership-aware diagnostics (`CallOrderFinding::roots`, `D60`) and the 4-tuple `best_anchor` (`D57`) deliver the conflict-free anchor in one place, with one engine. The measured placement gains (`L12`) came from the agent having a conflict-free target line, which `omnicoach code` now prints. `impact --diff` duplicated `omnicoach code --diff` (ordering findings) plus `slice` (callers) and had its own scoping bug (`D62`). |
| **D64** | **Remove the `MatchRank::TokenOverlap` identifier-token fallback from `find` and `slice`.** Match ranks are exact, prefix, and substring. `slice` takes required positional symbols plus a repeatable `--path <PATH>` that restricts the search, instead of guessing whether a positional argument is a directory or splitting arguments on commas. | The fallback was speculative fuzzy matching: its only evidence was one task whose prompt named a symbol that did not exist yet at the base commit (`L16`), and splitting a query into identifier tokens returns noisy hits (any declaration sharing two common tokens such as `rule` and `config`). With exact, prefix, and substring ranks only, an empty result is unambiguous, and the agent can shorten the pattern or fall back to `rg`. An explicit `--path` flag removes the ambiguity between symbols and paths. |
| **D65** | **Derive the default depth from the target instead of the `8 KB` size guard (`D56`).** Without `--depth`, a single file renders at full depth and a directory or several files render at module depth (`ProjectDepth::ModuleOnly`); an explicit `--depth` is always honored. Module-depth graphs with more than `20` modules omit per-module edges and say so in a notice line under the title (`// Module edges omitted for N modules; graph a single component's directory to see them.`); component edges are always shown. Peer lists stay visibly capped (`... (+N more)`, `2` peers per module, `6` per component), and so do empty modules per component (`... (+N more modules in X)`). | The guard rendered a full graph and silently downgraded it to module depth when the output crossed `8 KB`, so the depth an agent received depended on repository size rather than on the request. Choosing the depth from the target keeps the module overview that the guard fell back to (`L14`) as the predictable directory default, and every omission is stated in the output. Measured on this repository: `omnicoach graph src` (module depth, with the notice) `8.9 KB` / `133` lines, `omnicoach graph src/code_lint` `2.2 KB`, `omnicoach graph src/code_lint/graph` `516 B`, `omnicoach graph src/config.rs` `3.5 KB`, all below the `10 KB` inline truncation boundary. |
| **D66** | **Drop `**/*_test.rs` from the default Rust test patterns (`DEFAULT_TEST_PATTERNS` in `src/code_lint/project/config.rs`).** | The default pattern classified production rule files such as `src/code_lint/rules/multi_phase_test.rs` and `src/code_lint/rules/test_calls_test.rs` as tests, so neither `omnicoach code` nor `omnicoach graph` covered them. Rust tests live in `tests/`, `tests.rs`, or inline `#[cfg(test)]` modules, which the remaining defaults and the AST already handle. The earlier graph-only special case (`ContextConfig::has_custom_test_patterns` and an `is_excluded_test_path` exception in `src/code_lint/graph.rs`) was not kept: the default itself was wrong, so the fix belongs in the default. Projects that name test files `*_test.rs` can add the pattern to `[context] test-patterns`. |
