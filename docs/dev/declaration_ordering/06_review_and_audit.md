# Phase 6: Review & Audit — Declaration Ordering (`Topic::DECLARATION_ORDER`)

> [!IMPORTANT]
> **Status**: **COMPLETED**

---

## 1. Review Protocol

The entire 7-rule `Topic::DECLARATION_ORDER` batch (`field-after-method`, `associated-item-after-method`, `constructor-after-method`, `uncolocated-helper`, `private-before-public-function`, `callee-before-caller`, `statement-after-main-guard`) was audited across two dimensions:
1. **Code, Call-Graph Soundness & Tests Audit**: audited the shared AST and call-cluster extractors ([src/code_lint/ast.rs](../../../src/code_lint/ast.rs), [src/code_lint/ast/python.rs](../../../src/code_lint/ast/python.rs), [src/code_lint/ast/python/classes.rs](../../../src/code_lint/ast/python/classes.rs), [src/code_lint/ast/rust.rs](../../../src/code_lint/ast/rust.rs)), the 7 rule modules, priority-partitioned mutual exclusion (`P1 -> P2 -> P3`), and self-dogfooding across all 35 files in `src/`.
2. **User-Facing Text & Documentation Audit**: audited `ViolationTemplate`, `Classification`, `RuleDoc`, `Example`s, [decisions/011_colocated_abstraction_ordering.md](../../../decisions/011_colocated_abstraction_ordering.md), [docs/dev/tag_guide.md](../../tag_guide.md), [docs/dev/naming_and_message_style_guide.md](../../naming_and_message_style_guide.md), [ROADMAP.md](../../../ROADMAP.md), and [01_understand.md](01_understand.md)–[05_cleanup.md](05_cleanup.md).

## 2. Code & Tests Review Findings and Resolutions

| # | Severity | Finding | Resolution |
| :--- | :--- | :--- | :--- |
| **C1** | Medium (Bug) | **Doc comments before `#[cfg(test)]` / `#[test]` bypassed `is_in_rust_inline_test`**: In `ra_ap_syntax`, outer doc comments (`/// ...`) are leading token children of an item's `SyntaxNode` before any `ast::Attr` child. `collect_inline_test_ranges_rec` in [src/code_lint/ast/rust.rs](../../../src/code_lint/ast/rust.rs) started ranges at `first_attribute_start` instead of `node.text_range().start()`, so `file.is_in_rust_inline_test(item.syntax().text_range().start().into())` returned `false` whenever a `#[cfg(test)]` item carried a `///` doc comment. | **Fixed**: `collect_inline_test_ranges_rec` records `node.text_range().start()..node.text_range().end()`. Added `/// Test-only helper.` above `#[cfg(test)]` in `pass` test cases of `constructor_after_method.rs`, `private_before_public_function.rs`, and `associated_item_after_method.rs`. |
| **C2** | Medium (False Positive) | **Rust `new_*` / `try_new_*` associated functions returning an unrelated type were flagged as constructors**: `collect_type_method_scopes` and `build_rust_impl_callable_scope` in [src/code_lint/ast/rust.rs](../../../src/code_lint/ast/rust.rs) did not check whether the function's return type referenced `Self` or `type_name`, so a factory for another type (`pub fn new_request_id() -> u64` inside `impl Server`) was classified as a constructor of `Server`. | **Fixed**: Added `returns_self_type(function, &type_name)` checking that `function.ret_type()` contains a `SELF_TYPE_KW` (`Self`) or `IDENT` (`type_name`) token, and covered `pub fn new_request_id() -> u64` in `new_fn_not_returning_self_exempt` in [src/code_lint/rules/constructor_after_method.rs](../../../src/code_lint/rules/constructor_after_method.rs). |
| **C3** | Medium (False Positive) | **Closure parameters inside Rust `impl` methods caused false bridged call edges in `build_rust_module_callable_scopes`**: When bridging module-level function calls through `impl` blocks in the same module, scanning `impl_item.syntax()` with an empty `local_names` set caused closure parameter `\|collection_type\|` in `PythonCollectionType::joined_paths` ([src/code_lint/ast/python/annotations.rs](../../../src/code_lint/ast/python/annotations.rs)) to match module function `pub fn collection_type`. | **Fixed**: Extracted `collect_rust_impl_callees` in [src/code_lint/ast/rust.rs](../../../src/code_lint/ast/rust.rs), which collects `collect_rust_fn_local_names(&method)` for each `ast::AssocItem::Fn` in the `impl` block before resolving module-level function references. |
| **C4** | Low (False Positive) | **Overloaded Python property setters and `@<prop>.getter` were not grouped with the property**: In `group_python_callables` ([src/code_lint/ast/python/classes.rs](../../../src/code_lint/ast/python/classes.rs)), when a non-overloaded `@property` getter was followed by a private helper and then `@overload` stubs for its setter, `seen.has_overload` was `false`, so the setter's `@overload` stub was emitted as a new public method. | **Fixed**: Updated `continues_overload` to `is_overload \|\| (seen.has_overload && !seen.has_non_overload)` and included `"getter"` alongside `"setter" \| "deleter"` in `is_property_accessor`. Covered in `property_accessors_grouped_at_first_definition` in [src/code_lint/rules/private_before_public_function.rs](../../../src/code_lint/rules/private_before_public_function.rs). |
| **C5** | Low (Duplication) | **Duplicated `TypeAlias` and `Const` arms in `collect_misplaced_assoc_items`**: Both arms in [src/code_lint/ast/rust.rs](../../../src/code_lint/ast/rust.rs) repeated the same 10-line `RustAssociatedItemAfterMethod` construction block. | **Fixed**: Extracted `let misplaced_name = match assoc_item { ... };` and pushed once. |
| **C6** | High (RICR / Ergonomics) | **1-place `uncolocated-helper` contorted public-first types and small utility modules**: Requiring every 1-user helper to sit immediately below its consumer wedged multi-line helpers (`parse_single`, `parse_comment_text`, `find_directive_prefix`) between a type's constructor and its remaining public API (`InterceptedCommand`, `SuppressionTracker`, `CommentIndex`) and produced zig-zag `pub` / `fn` alternation in small modules (`test_utils.rs`, `scopes.rs`), while failing to catch 2-user helpers stranded in the middle of a `pub fn` block (`read_config_file` in `rule_selection.rs`). | **Fixed**: Refined `uncolocated-helper` (`is_valid_helper_placement` in [src/code_lint/ast.rs](../../../src/code_lint/ast.rs)) so that once a private helper is below its public callers (`pos > max(Roots(h))`), it is valid in **two places**: **Place 1** (immediately after its single consumer for `\|Roots(h)\| == 1`) or **Place 2** (in the trailing private helper section after `last_pub` for `\|Roots(h)\| >= 1`, without splitting a single owner's helpers between both places). |
| **C7** | High (RICR / API Ergonomics) | **`Public -> Public` `callee-before-caller` inverted foundational public APIs and separated colocated `const`s / `struct`s from their `pub fn`s**: Enforcing `caller < callee` between peer public entrypoints forced wrappers and test runners (`LineIndex::line`, `LanguageText::render`, `Config::is_rule_enabled_for_path`, `Facet::matches_label`, `CodeRule::check_banned_calls*`, `assert_rule_pass`) above their core primitives (`lookup`, `resolve_for_lang`, `is_rule_enabled`, `label`, `diagnostic_at_node`, `run_code_rule`), and separated colocated `const`s/`struct`s (`MUTATING_METHODS`, `SELF_PARAMETER`, `PythonReturnTypeUnion`) from their `pub fn`s in `python.rs`, `functions.rs`, and `annotations.rs`. | **Fixed**: Restricted `callee-before-caller` in `analyze_callable_scope` ([src/code_lint/ast.rs](../../../src/code_lint/ast.rs)) to `Private -> Private` call edges only (`MethodVisibility::Private` for both caller and callee), and restored natural `pub fn` ordering and `const`/`struct` locality across all 9 affected files in `src/`. |
| **C8** | Low (Duplication) | **Duplicated 35-line inherent `impl` method extraction loop in `src/code_lint/ast/rust.rs`**: `collect_type_method_scopes` and `build_rust_impl_callable_scope` duplicated the exact same attribute/visibility/constructor/receiver extraction logic over `assoc_items()`. | **Fixed**: Extracted `collect_rust_impl_methods(&impl_item, &type_name, &inline_test_ranges)` in [src/code_lint/ast/rust.rs](../../../src/code_lint/ast/rust.rs) and reused it in both functions. |
| **C9** | Medium (False Positive) | **`is_at_scope_end` rejected Place 2 for a first constructor's helper when a second constructor existed**: In `is_valid_helper_placement` ([src/code_lint/ast.rs](../../../src/code_lint/ast.rs)), `((owner + 1)..last_pub_idx).all(\|mid\| items[mid].is_constructor \|\| ...)` caused a second constructor at `mid` (`__init__` after `__new__`, or `try_new` after `new`) to satisfy the `mid` predicate when `last_pub_idx` was a non-constructor public method, making `is_at_scope_end` false for the first constructor's exclusive helper in Place 2. | **Fixed**: Simplified `is_at_scope_end` to `pos > last_pub_idx && ((owner + 1)..last_pub_idx).all(\|mid\| roots_of[mid] != *roots)`, which directly checks that the single owner did not already place another of its exclusive helpers in Place 1 before `last_pub_idx`. Covered in `second_constructor_keeps_trailing_section_valid` (Python and Rust) in [src/code_lint/rules/uncolocated_helper.rs](../../../src/code_lint/rules/uncolocated_helper.rs). |
| **C10** | Low (False Positive) | **Python `build_module_callable_scopes` did not exclude method-local bindings when bridging calls through `Stmt::ClassDef`**: Unlike Rust's `collect_rust_impl_callees` (`C3`), `build_module_callable_scopes` in [src/code_lint/ast/python/classes.rs](../../../src/code_lint/ast/python/classes.rs) passed `&empty_locals` when scanning `Stmt::ClassDef` bodies for module-level callees, so a method parameter or local variable named `_helper` bridged a false call edge to module-level `def _helper()`. | **Fixed**: Collected `collect_local_bound_names(&func.parameters, &func.body)` per method inside `Stmt::ClassDef` when bridging class references to module-level functions, and covered in `class_method_local_binding_does_not_bridge_module_helper` in [src/code_lint/rules/uncolocated_helper.rs](../../../src/code_lint/rules/uncolocated_helper.rs). |
