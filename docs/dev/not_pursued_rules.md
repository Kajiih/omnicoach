# Not Pursued Rules

Evaluated rule candidates and sub-checks that were intentionally not added to Omni, along with why and the external linter or type-checker configuration that covers them where applicable.

- **Magic numbers in comparisons, bare HTTP status codes, path composition, and correspondence-signaling test constants**: magic numbers in comparisons are covered by Ruff `PLR2004`, bare HTTP status codes are too narrow, path composition is covered by Ruff `PTH`, and test correspondence-signaling or same-value-different-meaning constants require semantic understanding.
- **Time-unit literal arithmetic** (`24 * 60 * 60`, `60 * 60`, `86400`, `3600`): self-defeating in `Duration::from_secs(60 * 60)` / `Duration::from_secs(86400)` and false-positive-prone on protocol/serialization boundaries (HTTP `Cache-Control`, JWT `exp`, Unix epoch math); duration-named bindings are already caught by `primitive-duration`.
- **Sparse positional access (`row[0]`, `row[7]`), `re.Match` group indexing (`m[1]`, `m[2]`), Rust fixed-size array indexing (`arr[0]`, `arr[1]`), and multi-field Rust tuple structs**: sparse gaps (`max-placeholders = 2`) occur on external tabular/wire data where the caller does not own the producer type (in-repo tuple producers are already flagged by `positional-tuple-return`, and `.0`/`.1` use sites on multi-field tuple structs are already flagged by `repeated-index-access`); `m[1]`, `m[2]` is already flagged by `repeated-index-access` without needing type inference (`m.groups()` is unsound when more than two capture groups exist); and `arr[0]` cannot be distinguished from `vec[0]` or `slice[0]` without `rustc` type resolution.
- **Rust doc-comment analogues** (`undocumented-nontrivial-function`, `deferral-docstring`, `unexplained-parameter`, `verb-led-returns-section`, `verb-led-property-docstring`, `unexplained-optional-return`): Rust item documentation is covered by `rustc` `#![warn(missing_docs)]` and `clippy::missing_docs_in_private_items`, `rustdoc` automatically inherits trait method documentation onto undocumented `impl` methods, and Rustdoc has no `Args:` / `Returns:` section convention, default arguments, or property getters (and standard-library getter doc comments conventionally open with `"Returns ..."`).
- **`manual-enum-name-map` (`{"FOO": Enum.FOO}` dicts) and `overprecise-float-in-tests` (test floats with >N digits)**: dropped for low signal-to-complexity ratio—identity enum-name dicts are vanishingly rare once narrowed to avoid wire-format/alias false positives (and `match` is standard Rust without `strum`), while digit-count thresholds on test floats create suppression noise on legitimate numerical/coordinate/golden test vectors (`clippy::excessive_precision` already covers digits beyond `f32`/`f64` representability).
- **`CatchGenericExceptionRule`**: covered by Ruff `[tool.ruff.lint] extend-select = ["E722", "BLE001", "TRY002", "TRY203", "TRY400", "S110", "S112"]` (plus `logger-objects = ["loguru.logger"]` and `[tool.ruff.lint.flake8-bandit] check-typed-exception = true`).
- **`EmptyInitRule`**: covered 1:1 by Ruff `[tool.ruff.lint] preview = true`, `extend-select = ["RUF067", "INP001"]`, and `[tool.ruff.lint.ruff] strictly-empty-init-modules = true` (or `false` for library facades; add `extend-ignore = ["D104"]` if `pydocstyle` `D` is enabled).
- **`LoggerRedundantExceptionRule`**: covered by Ruff `[tool.ruff.lint] extend-select = ["TRY400", "TRY401", "G201", "LOG004", "LOG007", "LOG014"]` (plus `logger-objects = ["loguru.logger"]` and `extend-ignore = ["PLE1205"]` when using Loguru).
- **`LoggerPrintfFormatRule` Branch B (`"..." % ...` in logs)**: covered by Ruff `[tool.ruff.lint] extend-select = ["UP031", "G001", "G002", "G003", "G004"]` (and Branch A for Loguru today via Pylint `E1205` with `[tool.pylint.logging] logging-format-style = "new"` and `logging-modules = ["loguru"]`).
- **`LoggerPositionalPlaceholderRule` (banning matched named placeholders like `logger.info("{count}", count=10)`)**: intentionally narrowed to `unmatched-logger-placeholder`.
- **`InstanceAttributeAnnotationRule` Checks 2 & 3**: Check 2 conflicts with PEP 526/PEP 591/Pydantic/attrs/`__slots__`; Check 3 is covered by Mypy (`[tool.mypy] enable_error_code = ["no-redef"]`), Pyright (`[tool.pyright] reportUninitializedInstanceVariable = "warning"`, `reportGeneralTypeIssues = "error"`), Ruff (`RUF012`), and Pylint (`W0201`).
- **`DefineBeforeUseRule` (`call-before-definition`), file-wide `constant-after-function`, and rigid module-level item-kind / visibility ordering**: top-level undefined/forward references in Python are covered by Ruff `[tool.ruff.lint] extend-select = ["F821", "F823"]` and Pylint `E0601` (`used-before-assignment`), module-level import placement is covered by Ruff `E402` (`module-import-not-at-top-of-file`), and rigid module-level item-kind or constant-before-function ordering (`clippy::arbitrary_source_item_ordering`) breaks cohesion by splitting types and functions from their colocated constants, constructors, errors, and helpers.
- **`unbuilt-pydantic-annotation` / forward references in Pydantic or `Annotated` annotations**: under `from __future__ import annotations`, forward references to runtime metadata in `Annotated[T, metadata]` (such as validators, serializers, or constraints) do not fail at module import time; instead, runtime frameworks like Pydantic defer model building and leave the model incomplete (`__pydantic_complete__ == False`) until it is rebuilt (explicitly with `model_rebuild()` or automatically on first validation). Static type checkers (`basedpyright` `reportUndefinedVariable`, `mypy` `used-before-def`) already flag undefined forward references in annotations. Conversely, forward references to *types* in model annotations are valid and idiomatic in Pydantic v2 via deferred rebuild / `model_rebuild()`. Flagging forward type references in annotations would create false positives on supported Pydantic patterns, while forward references to metadata expressions that leave models incomplete are already surfaced by standard type checkers.
- **`AvoidOptionalOrNoneRule` Check 1 (`Optional[T]` syntax)**: covered by Ruff `target-version = "py310"` and `[tool.ruff.lint] extend-select = ["UP007", "UP045", "RUF013", "RUF036"]`; scalar returns, attributes, and parameters under Check 2 are intentionally not flagged.
- **`quote-wrapped-placeholder` for Rust**: not extended to Rust because `std::fmt::Debug` (`{:?}`) is not "quoted `Display`" (for structs and enums implementing `Display` + `#[derive(Debug)]`, `{:?}` dumps internal struct layout or unquoted enum variant names rather than quoting the `Display` output, and for strings `{:?}` forces double quotes and Rust escape syntax).
- **Values formatted into SQL strings (SQL injection)**: covered by Ruff `[tool.ruff.lint] extend-select = ["S608"]` (`hardcoded-sql-expression`), whose fix is a parameterized query. `quote-wrapped-placeholder` does not special-case SQL.
- **`PrimitiveTypeSuggestionsRule`, `FloatToDecimalSuggestionsRule`, `DecimalZeroFormattingRule`** ([03_design.md](banned_type_annotations/03_design.md)): primitive-to-domain-type (`int`/`str` → `Port`/`Host`) and `float` → `Decimal` suggestions on generic identifiers have extreme false-positive rates , and `Decimal("0.00")` → `Decimal(0)` changes the scale/exponent (`-2` vs `0`) used by `quantize()` and `str()`. Fixed-length positional tuples and project-configured composite annotations from `BannedTypeAnnotationsRule` are covered by `positional-tuple-return`, `positional-tuple-parameter`, `positional-tuple-attribute`, and `adhoc-type-annotation`; simple banned symbol imports remain covered by Ruff `[tool.ruff.lint.flake8-tidy-imports.banned-api]` (`TID251`).
- **Unscoped third-party suppression directives** (bare `# noqa`, `# type: ignore`, `# ty: ignore`, ...): owned by each tool: Ruff `[tool.ruff.lint] extend-select = ["PGH003", "PGH004", "RUF103"]`, mypy `enable_error_code = ["ignore-without-code"]`, `ty` `blanket-ignore-comment`, basedpyright `reportIgnoreCommentWithoutRule`. Their missing reasons are covered by `missing-suppression-reason` ([03_design.md](suppression_comments/03_design.md) §0).
- **`BannedDoubleBackticksRule` (RST-style ``` ``code`` ``` in docstrings) and `check_comments` (comment capitalization and sentence structure)**: dropped as low-signal style preferences.
- **`check_markdown_file` (absolute or broken relative links in Markdown)**: Omni lints Python and Rust sources only; use a dedicated link checker such as `lychee` or `markdown-link-check`.
- **Incomplete `Args:` sections and general `Returns:` / `Yields:` / `Raises:` section checks**: incomplete `Args:` sections once an `Args:` header is present are covered by stable Ruff `D417` (`undocumented-param`); structured docstrings missing `Returns:` / `Yields:` are covered by preview Ruff `DOC201` / `DOC402` (`[tool.ruff.lint.pydoclint] ignore-one-line-docstrings = true`); `Raises:` checks are left to Ruff `DOC501` because syntactic `raise` scanning cannot distinguish public interface exceptions from internal precondition checks.
- **`wall-clock-in-tests` (banning `datetime.now()`, `date.today()`, `time.time()`, `SystemTime::now()` inside tests)**: dropped because primary testing references (Fowler, *Eradicating Non-Determinism in Tests*; Meszaros, *xUnit Test Patterns*; *Software Engineering at Google*, ch. 12–13) locate the defect in the **SUT** reading the live system clock without an injectable seam, not in test code binding a timestamp. In Python, `freezegun` (`@freeze_time`) and `time-machine` (`@time_machine.travel` or `conftest.py` fixtures) patch `datetime.now` and `time.time` so test calls read the frozen clock (invisible to single-file AST when applied via fixtures), and real TLS/JWT/DB/filesystem tests require relative windows (`now - 1h .. now + 1h` or `mtime >= before_write`) against the live clock. Timezone-naive datetime calls are already covered by Ruff `flake8-datetimez` (`DTZ001`–`DTZ012`).
- **`ServiceLifecycleRule` (`connect`/`disconnect`/`close` without context manager, `stop` without `join`, and `@classmethod` decorator order)**: Check 1 (`def connect`/`disconnect`/`close` without `__enter__`/`__aenter__`) and Check 2 (`def stop` with `threading` imported and no `.join()`) have high false-positive rates on helper classes, callbacks, and signal/event-based thread cancellation where lifecycle ownership lives on a caller or `ExitStack`; Check 3 (`@classmethod` placed below a function-wrapping decorator) is covered by Ruff `[tool.ruff.lint] preview = true`, `extend-select = ["RUF074"]` (`incorrect-decorator-order`), which flags `@abstractmethod` before `@classmethod` / `@staticmethod` / `@property` and `@contextmanager` / `@asynccontextmanager` / `@functools.cache` / `@functools.lru_cache` before `@classmethod` (alongside `PLC0206` / `PLE0117` / `B019`; note that `RUF074` does not yet cover those four function-wrapping decorators before `@staticmethod`, which raises `TypeError` on `instance.method()` in Python $\ge 3.10$, or `@classmethod` / `@staticmethod` before `@functools.singledispatchmethod`, which raises `TypeError: 'singledispatchmethod' object is not callable`).
